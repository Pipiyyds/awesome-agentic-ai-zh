# 辅导与验收规则

## 每一节课

1. 用一个真实需求提出问题：今天为什么需要这个概念？
2. 新术语用两三句白话讲是什么、有什么用和类比，再给英文术语；每次控制 3-5 个新核心词。
3. 只读当前原章核心和 1-2 个必要辅助来源；不让资料搜集挤占实作。
4. 用户先跑原例，再只改一个变量并重跑；先离线/假数据，live 模型结果分开记录。
5. 给一个同概念变式，让用户独立完成；卡住时先逐步提示，再给可解释示例。
6. 检查正常、错误、边界与停止条件；依据证据登记状态，记录最关键失败。
7. 更新下一任务与本周时间偏差。发送前复核事实、条件、可执行性和结果，并列关键修订。

## 四级技能证据

| 状态 | 最少证据 |
| --- | --- |
| 读过 read | 指定段落已读，并能指出核心问题。 |
| 跑过 run | 输入、命令、输出与错误记录，区分 mock 和 live。 |
| 理解 explain | 能用自己的话说明数据、动作、结果与停止的因果。 |
| 掌握 transfer | 不照抄完整答案，换输入/工具做变式，解释取舍并修复一个故障。 |

原作者完成检查/rubric 与个人验收一起用。AI 代写代码只算产物；不能推定用户已经掌握。

## 省时间的方法

共用节点只补差异；主要 CLI 选一个，框架深入一个；先稳定普通脚本与单 Agent 基线，只有质量、成本或状态管理有证据需求才增加复杂度。卡住 20 分钟仍无新信息，就保留最小复现和错误，再针对原因求助。

第一轮 4 个任务后用实际耗时重新估计进度，不强行用计划工时评价用户。考试周降低投入也保留当前节点与证据。

## 资料新鲜度

上游快照不是最新能力保证。到实际安装/运行节点时核对官方产品文档、API、权限、认证与价格；核对当前设备和工具实际支持的停止机制。不能从文档推断已接入，不能从一次成功推断稳定可靠。
